# Файлы

Файлы: `core/File.hpp`, `core/File.cpp`, `core/BinaryBlock.hpp`, `core/BinaryBlock.cpp`. Два класса для работы с файлами как с байтами.
Содержимое файлов читают и пишут только через `File`: потоков `std::ifstream` и `std::ofstream` в коде нет. `FileSystem` отвечает за пути и папки, а не за содержимое.
Формат файла они не знают. Его описывает тот, кто их использует, например [[Файл сцены#Файл модели]].

## File

Файл на диске, закрывается сам. Только перемещается, не копируется. Внутри один `std::filebuf`, его тип виден только в `File.cpp`.
Путь переводит `ToFilesystemPath` (`core/FilesystemPath.hpp`, только для `core`), поэтому пути в UTF-8 работают как везде.

Клиент сам создаёт `File`, открывает его, читает или пишет и закрывает, `File` не прячет эти шаги:

```cpp
std::error_code error;
FileSystem::CreateDirectories(path.Parent(), error);   // папки нужны не всем, их создаёт клиент

File file;
if (auto opened = file.Open(path, FileMode::Write); !opened)   // заменяет содержимое
    return UnexpectedSerializationError(opened.error().message, LogSource);   // пишет в лог
if (auto written = file.Write(block); !written)
    return UnexpectedSerializationError(written.error().message, LogSource);
if (auto closed = file.Close(); !closed)         // ошибка записи может проявиться только здесь
    return UnexpectedSerializationError(closed.error().message, LogSource);
return {};
```

Чтение, текст из блока без копии:

```cpp
File file;
if (auto opened = file.Open(path, FileMode::Read); !opened)
    return UnexpectedSerializationError(opened.error().message, LogSource);   // пишет в лог
const auto block = file.ReadAll();
if (!block)
    return UnexpectedSerializationError(block.error().message, LogSource);
const StringView text = *block->ReadText(0, block->Size());   // живёт, пока жив block
```

- `FileMode::Read` требует существующий обычный файл. Папка или отсутствующий файл дают ошибку.
- `FileMode::Write` создаёт файл в существующей папке или очищает существующий. Папки `Open` не создаёт: нет папки, значит ошибка.
- `Open` у открытого файла сначала закрывает его. Если закрыть не удалось, новый файл не открывается и `Open` возвращает ошибку.
- `ReadAll` читает файл целиком за один вызов и возвращает `BinaryBlock`.
- `Flush` отдаёт записанное системе: его уже можно прочитать, и ошибка записи проявится здесь. Файл остаётся открытым.
- Файл всегда двоичный: `\n` остаётся `\n` и на Windows.
- Вызов не того рода (`Write` у файла для чтения, `ReadAll` у файла для записи) даёт ошибку, как и вызов у файла, который не открыт: до `Open`, после `Close` или после перемещения. `Close` у такого файла ничего не делает.
- Ошибка возвращается вызывающему как `EngineResult`, с путём в сообщении и кодом `ErrorCode::FileAccessFailed`. Деструктор закрывает файл, но сообщить об ошибке записи не может, поэтому после записи вызывайте `Close`.
- `File` не зависит от лога и ничего в него не пишет. Что считать ошибкой и что сообщать, решает вызывающий код: отсутствие шейдера в одной из двух папок — не ошибка, а отсутствие файла сцены — ошибка, и её пишет в лог `Serializer`.
- Владелец тот, кто создал файл. Привязки к потоку нет, но работать с файлом можно только из одного потока за раз.

Запись не атомарная: при сбое файл может остаться неполным.

## BinaryBlock

Владеет байтами подряд: это содержимое файла или то, что будет в него записано. Значения проходят с их раскладкой в памяти, поэтому подходят только типы, которые можно копировать побайтово (`BinaryValue`). Порядок байт и версию формата задаёт тот, кто описывает формат.

```cpp
BinaryBlock block;
block.AppendText("ELMM");
block.Append(uint32_t { 3 });
block.AlignTo(16);                               // нули до кратного размера
block.AppendArray<Vertex>(meshData.vertices);

const auto version = block.Read<uint32_t>(4);    // std::optional, пусто за границей
const bool read = block.ReadArray<Vertex>(16, vertices);
const auto text = block.ReadText(0, 4);          // StringView, живёт пока блок не меняется
```

- Запись идёт в конец блока, чтение идёт по смещению и не меняет блок.
- Значение, которое не помещается в блок целиком, не читается: `nullopt` или `false`. Проверка не переполняется даже на огромных смещениях и счётчиках из испорченного файла.
- `==` сравнивает байты.
- Владелец тот, кто держит блок. Работать с ним можно только из одного потока за раз.
