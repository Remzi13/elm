# Пакет редактора

Пакет — редактор, готовый к запуску без исходников и сборки. CI публикует его отдельно для Linux и Windows.
Правила раскладки лежат в `cmake/EditorPackage.cmake`, это компонент установки CMake `EditorPackage`.

## Что внутри

- `editor` и рядом `elm`: **Run Standalone** запускает `elm`, **Build Game** копирует его в игру ([[Проекты#Сборка]]);
- `shaders/` — шейдеры, скомпилированные под платформу пакета: SPIR-V на Linux, DXIL на Windows;
- `resources/` — шрифт редактора;
- `docs/` — эта документация, в том числе `Первый проект.html` и `Справочник.html`;
- `projects/` — тестовые проекты Sandbox, Race и Test, без их папок `Build/`;
- `.settings` из `cmake/EditorPackage.settings`: корень движка — папка пакета, в списке недавних проектов — тестовые.
  Рабочий `.settings` из корня репозитория в пакет не попадает;
- на Windows — библиотеки Visual C++ рядом с программами, Redistributable ставить не нужно. Build Game копирует их в игру.

## Запуск

Запускайте редактор из папки пакета: `.settings` ищется вверх от текущего каталога, и по нему определяется корень
движка. При первом запуске открывается Project Hub с тестовыми проектами.

Что нужно на машине:
- Windows: 64-битная система с поддержкой Direct3D 12;
- Linux: x86-64, glibc и libstdc++ не старше, чем в Ubuntu 24.04, загрузчик Vulkan (`libvulkan1`) и драйвер с Vulkan 1.3.

Пакет собран с опциями игры для выпуска (`-DELM_PROFILING=OFF -DELM_DEBUG_DRAW=OFF`), потому что собранная игра — копия
его `elm`. Tracy в нём нет. В Run Standalone и в собранной игре не работает отладочная отрисовка, `elm.debug` там ничего
не рисует. В самом редакторе она работает.

## CI

`.github/workflows/ci.yml` запускается на push и pull request в `main`. Задания: Linux и Windows, в каждой конфигурации
Debug и Release. Все четыре собирают `elm_tests` и `editor` и прогоняют `elm_tests` и `editor --editor-selftest`.

Задания Release дополнительно:
1. раскладывают пакет командой `cmake --install`;
2. проверяют копию пакета вне репозитория: `editor --editor-selftest` и `editor --build projects/Test`;
3. публикуют артефакт на странице запуска в GitHub Actions.

| Платформа | Артефакт |
|---|---|
| Linux | `elm-editor-linux-x64.tar.gz`: свой архив, потому что zip артефакта теряет права на запуск |
| Windows | `elm-editor-windows-x64`: GitHub отдаёт его как zip |

Окно с рендером CI не запускает: на машинах CI нет GPU.

## Собрать локально

```
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DELM_PROFILING=OFF -DELM_DEBUG_DRAW=OFF
cmake --build build --config Release --target editor
cmake --install build --config Release --component EditorPackage --prefix dist/elm-editor
```

В пакет идут файлы рабочей копии как есть, включая незакоммиченные правки проектов. Без `--component` установка
захватит ещё и файлы зависимостей.

Каталог `../elm_deps` общий для всех каталогов сборки: там лежат и исходники, и сборка зависимостей. На Linux, где
конфигурация одна на каталог, второй каталог сборки с Release перезапишет библиотеки зависимостей Debug-сборки в первом.
Для Release держите отдельную копию репозитория.
