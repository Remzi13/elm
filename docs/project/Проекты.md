# Проекты

> **Статус: все 7 этапов сделаны** (раздел [[#Что уже есть]]). Что из плана отложено — в разделе
> [[#Этапы]] у каждого этапа.

## Что уже есть

- Проект-пример `projects/Sandbox/`: файл `Sandbox.elmproject` и `assets/` (сцены, скрипты, тесты).
  Шрифт редактора лежит в `resources/fonts/` движка, шейдеры — в `shaders/`.
- `project::Project` (`project/Project.*`): файл проекта, `ProjectDesc` (`name`, `entry.mainModule`),
  папки `Assets()`, `Scenes()`, `Models()`, `Scripts()`. `Project::FindFile` превращает папку
  `Games/CoinRush` в `Games/CoinRush/CoinRush.elmproject`. Читает файл `resmgr::Serializer::LoadProject`
  (`formatVersion` 1, `name` обязателен, `entry` нет — `mainModule = "main"`).
- Запуск: `Engine --project <папка или .elmproject>` (относительный путь — от корня движка), без
  аргумента — последний проект (`Core/Project/Last` в `.settings`). Без проекта редактор не стартует.
- Все пути игры берутся из `Project`. Модуль graphics о проекте не знает: окна Scene Hierarchy и Model
  Editor получают от `EngineApp` папки проекта (`SceneHierarchyWindow::Folders`, папку моделей), меню
  Project — `ProjectMenuDesc` (имя, файл, расширение, запрос `open`). Lua-биндинги берут проект из
  `EngineContext::project`, скрипты — корень `ScriptSystem::Init`. `AssetPaths` удалён.
- Главный модуль — `entry.mainModule` проекта, `ScriptSystem::Start(settings, mainModule)`. Настройки
  `Script/MainModule` больше нет.
- Смена проекта без перезапуска редактора: меню Project → Open Project / Reload Project, подтверждение,
  затем `ProjectMenuDesc::open` и `EngineApp::ApplyProjectRequest` в начале update (подробнее ниже).
- Self-test (`project::*`): поиск файла проекта, чтение и ошибки `.elmproject`, перезапуск скриптов с
  корнем другого проекта. Lua-тесты движка запускаются на `projects/Sandbox`.
- Этап 2. `project::AssetPath` — путь файла от папки `assets` (`models/Cube.model`), без `..` и корня;
  `AssetPath::In`/`Of` и `Project::Resolve`/`AssetPathOf`. Файл модели хранит `ModelManager` (`FileOf`). Сцена версии 7 ссылается на
  модели путями ассетов и не переписывает их файлы; модели без файла записывает
  `Serializer::SaveNewModels` под свободным именем ([[Файл сцены#Модели]]). Lua: `save_scene`,
  `load_scene` и `elm.models.load` принимают пути ассетов, у `Model` есть `file`.
- Этап 3. `ProjectEntry`: `startupScene` (путь ассета) и `mainModule`, хотя бы одно обязательно, а
  `entry` в `.elmproject` обязателен. Главный модуль работает только в Play, каждый Play и Stop дают
  свежую Lua-машину. Play Project (F5) и Play Scene (Shift+F5) над вьюпортом,
  `PlayStart`/`PlayTarget`, `EngineApp::MakePlayStart`. При открытии проекта в редактор загружается
  стартовая сцена ([[Редактор#Edit и Play]]).

- Этап 4. Ресурсы попадают в проект через импорт ([[#Импорт]]): оригинал — в `source/`, модели — в
  `models/`. Диалоги открытия и сохранения ассетов не выходят за папку `assets`. «New» в Scene Hierarchy
  начинает сцену под свободным именем, «New file» окна Scripts создаёт скрипт сущности по шаблону.

- Этап 5. Модуль `editor` с окнами, которым нужен проект: [[#Окно Project]] (ассеты и точка входа на
  вкладке Settings) и [[#Project Hub]]. Без проекта редактор стартует с Hub. Меню Project: Project Hub,
  Open, Recent, Reload.

- Этап 6. [[#Плеер]]: `Engine --project X --player` запускает игру без редактора, Run Standalone
  (Ctrl+F5, меню Project) — то же отдельным процессом из редактора.

- Этап 7. [[#Сборка]]: Project → Build Game или `Engine --build <проект>` собирает игру в
  `Build/<Имя>/`; собранный `<Имя>.exe` без аргументов играет свой проект.

Отличия от плана ниже, принятые при реализации этапа 1:
- `AssetPath` отложен до этапа 2: в этапе 1 им никто не пользуется.
- Отдельного `Settings` проекта нет: единственная настройка игры, главный модуль, стала полем
  `entry.mainModule`. Экземпляр настроек проекта появится вместе с первой настоящей настройкой игры.
- Lua-тесты остались в `projects/Sandbox`: они проверяют демо-скрипты этого проекта
  (`demos_test.lua`, стражи `npc.guard`). Решение 3 пересмотрено.
- `Reload` — это `open` того же файла. Вместо Save / Discard / Cancel — одно подтверждение «изменения
  потеряются»: признака изменения сцены пока нет (этап 5).

Проект — все данные одной игры: сцены, модели, скрипты, текстуры и настройки. Редактор работает
только с проектом: открывает, сохраняет, запускает и собирает его в готовую игру. Движок без
редактора (плеер) запускает тот же проект.

## Что мешает сейчас

- Корень один: `AssetPaths` статически отдаёт `<RootPath>/assets/...`. Данные движка (`shaders/`,
  шрифт редактора, `.meta/elm.lua`) и данные игры лежат вместе.
- `.settings` смешивает настройки игры (`Script/MainModule`) и редактора (каналы отладочной
  отрисовки, визуализация culling, `PlayOnStart`, `HotReload`). Оси ввода зашиты в `EngineApp::Init`.
- Модель не знает свой файл. `Serializer::SaveScene` при каждом сохранении заново пишет все модели в
  `modelDirectory` по `Model::name`. Импорт glTF держит модель только в памяти.
- Пути считаются от разных мест: сцена ссылается на модели от себя, `elm.model.load` — от `assets/`,
  `elm.engine.save_scene` — от `assets/scenes`.
- В Edit главный модуль получает `on_start`, а примеры начинают с `elm.engine.clear_scene()`: в проекте
  со стартовой сценой это стёрло бы её.
- `EngineApp` — это и рантайм, и редактор: без ImGui он не стартует.

## Сущности

| Сущность | Что это | Где |
|---|---|---|
| `Project` | открытый проект: имя, корень, `ProjectDesc`, настройки проекта. Владелец `EngineApp`, поток update | `project` |
| `ProjectDesc` | содержимое `<Name>.elmproject`: `formatVersion`, `name`, `entry`, настройки | `project` |
| `ProjectEntry` | точка входа: стартовая сцена и/или главный модуль, хотя бы одно задано | `project` |
| `AssetPath` | путь ассета от корня проекта (`models/Cube.model`): без `..` и абсолютных путей | `project` |
| `AssetType` | `Scene`, `Model`, `Script`, `Texture`, `Font`, `SourceModel` (gltf/glb), по расширению | `project` |
| `ProjectAssets` | каталог ассетов: скан папки, поиск по типу, слежение за изменениями | `project` |
| `ProjectMenuDesc` | открытый проект для меню Project и запрос `open` (перезагрузка — `open` того же файла), применяется в начале update | `graphics/ui` |
| `PlayStart` | с чего начинается Play: сцена (`SceneAsset*`, может не быть) и главный модуль | `script` |
| `ProjectWindow`, `ProjectSettingsPanel`, `ProjectHubWindow` | ассеты и настройки проекта в одном окне, стартовое окно | `editor` |
| `ProjectBuilder` | сборка проекта в папку готовой игры | `project` |

Модуль `project → core`, без Lua и GPU. `resmgr → project` (PRIVATE) читает `.elmproject` и переводит
пути ассетов. `Engine` и `script` (PRIVATE) используют `project`. graphics о проекте не знает: окна получают
от `EngineApp` обычные пути. Отдельного «менеджера проектов» нет: шаги
открытия, закрытия и запуска — методы своих систем, порядок задаёт `EngineApp`.

## Проект на диске

```
CoinRush/                      имя папки = имя игры
  CoinRush.elmproject          описание, точка входа, настройки проекта (в git)
  assets/
    scenes/  models/  scripts/  textures/
    source/                    оригиналы импорта (gltf/glb) для повторного импорта
    scripts/.luarc.json        генерируется, указывает на elm.lua движка
  .elm/                        локальное, в .gitignore: editor.settings (камера, открытая сцена), кэш
  Build/                       результат сборки, в .gitignore
```

```json
{
   "formatVersion": 1,
   "name": "CoinRush",
   "entry": { "startupScene": "scenes/level1.scene", "mainModule": "coin_rush.main" },
   "settings": { "Physics/...": 0 }

```

`FileSystem::RootPath()` — корень движка (шейдеры, шрифты редактора, `elm.lua`), `Project::Root()` —
корень игры. Путей проекта в статических функциях нет: `Project` передаётся через `ImGuiWindowContext`,
`EngineContext` и `ScriptSystem::Init`. Иначе смена проекта означала бы подмену глобального состояния.

## Принятые решения

1. **Ссылки на ассеты по пути (`AssetPath`), без GUID.** Переименование через окно Project исправляет
   ссылки в сценах. GUID и `.meta`-файлы — только если пути начнут мешать.
2. **Контент проекта лежит в `assets/`**, раскладка как сейчас.
3. ~~Lua-тесты движка не входят в проект~~ Пересмотрено: тесты проверяют демо-скрипты и остаются в
   проекте-примере `projects/Sandbox/`, на нём и запускается `--script-selftest`.
4. **Смена и перезагрузка проекта без перезапуска редактора** (см. ниже).
5. **Главный модуль работает только в Play.** В Edit Lua-машина нужна для props в Scene Hierarchyr (props по
   умолчанию) и консоли, `main.on_start` не вызывается.
6. **Каждый Play начинается со свежей Lua-машины**, как старт настоящей игры. Stop возвращает
   сцену из снимка и перезапускает Lua в Edit. Сейчас Stop состояние Lua не трогает: это меняется.

## Смена проекта без перезапуска редактора

Запрос меню Project (`ProjectMenuDesc::open`) применяется в начале `EngineApp::Update`, до
`PlayMode::ApplyRequest`, никогда изнутри Lua-вызова или отрисовки окна.

1. **Проверка.** Новый `.elmproject` читается и проверяется до закрытия текущего. Ошибка: остаёмся
   в текущем проекте, пишем в лог.
2. **Несохранённое.** Save / Discard / Cancel: сцена (`Scene::Revision()`), модель в ModelEditor,
   буферы окна Scripts.
3. **Закрытие.** Play → `PlayMode::Stop()`, `ScriptSystem::Shutdown()`, `PhysicsSystem::Clear()`,
   `Scene::Clear()`, `ModelManager::Clear()`, каналы `Script/*` в `DebugDraw`. Сохраняются настройки
   проекта и `.elm/editor.settings`.
4. **Окна проекта пересоздаются** (Scene Hierarchy, ModelEditor, Project, Scripts), окна редактора (Log, Profiler, Settings) живут дальше. Никакого `Reset` в каждом окне и
   никаких устаревших `NodeId`, путей и undo. Раскладка сохраняется: `imgui.ini` хранит её по имени окна.
5. **Открытие.** Настройки проекта загружаются в тот же экземпляр `Settings` (значения по умолчанию
   хранятся в `Settings::Entry`, ключи без значения в файле сбрасываются к ним), затем
   `ScriptSystem::Init(engine, project.Scripts())`, затем последняя открытая сцена или стартовая.

`Reload()` проходит тот же путь с тем же файлом: после `git pull` или ручной правки `.elmproject`.
Из Lua смена проекта недоступна: это действие редактора.

Что уже есть: `ScriptSystem::Restart()` делает Shutdown + Init с корнем скриптов; Clear в Scene
Hierarchy уже очищает сцену и модели при работающем render-потоке; у `PhysicsSystem` есть `Clear()`.

## Импорт

Файлы извне попадают в проект только через `resmgr::AssetImport` (`resmgr/AssetImport.*`):
- `CopyIntoProject(file, assetsFolder)` копирует оригинал в `source/<имя>/` (`source/<имя>_1/`, если такая
  папка уже есть), `.gltf` — вместе с буферами и картинками, на которые он ссылается (`buffers[].uri`,
  `images[].uri`, кроме `data:`). Ссылка за пределы папки `.gltf` — ошибка. Файл, который уже лежит в
  `assets`, не копируется.
- `ImportModel(file, assetsFolder)` — одна модель (`ProjectModel`: модель и её файл). `.model` проекта
  остаётся своим файлом. Для glTF оригинал копируется в `source/`, а модель записывается новым `.model`
  в `models/` (`Serializer::SaveNewModel`, имя без перезаписи: `Cube.model`, `Cube_1.model`, …).
- `ImportScene(gltf, assetsFolder)` — сцена glTF: оригинал в `source/`, каждая модель — новый `.model`,
  их файлы в `SceneAsset::modelFiles`.

Где в редакторе: «Import glTF...» и «Model from Disk» в Scene Hierarchy, «Import glTF Model» в Model Editor
(сессия импорта работает с копией из `source/`; модели остаются документом, пока их не сохранят или не
сохранят сцену). Открыть сцену или `.model` и сохранить их можно только внутри `assets`
(`ui::FileDialog::LimitTo`); импортировать — откуда угодно.

Ещё не сделано: повторный импорт из `source/`.

## Окно Project

`editor::ProjectWindow` — две вкладки. **Assets** показывает папку `assets` открытого проекта деревом (`project::ProjectAssets`:
папки сначала, потом файлы, по имени; папки на `.`, как `.meta`, скрыты; читается кнопкой Refresh).
- Тип файла — `project::AssetType` по расширению: `Scene`, `Model`, `Script`, `SourceModel` (gltf/glb),
  `Texture`, `Other`. Поиск по имени и фильтр по типу показывают найденное списком путей.
- Двойной клик или «Open» открывает сцену в Scene Hierarchy, `.model` в Model Editor, скрипт в окне
  Scripts — запросами `OpenSceneFile`, `OpenModelFile`, `OpenScriptFile` (`graphics/ui/WindowMessages.hpp`).
- `.model` или glTF перетаскивается в дерево Scene Hierarchy (`ModelFilePayload`) и становится новым
  корневым узлом; glTF при этом импортируется ([[#Импорт]]).
- Контекстное меню: «Set as Startup Scene» у сцены, «New Folder...» у папки и кнопка New Folder для
  корня. Стартовая сцена помечена «startup».

**Settings** (`editor::ProjectSettingsPanel`) выбирает стартовую сцену из сцен проекта и главный модуль
из его скриптов. Save пишет `.elmproject` (`resmgr::Serializer::SaveProject`); точку входа без сцены и
модуля не сохранить. «Set as Startup Scene» на вкладке Assets и Save на вкладке Settings меняют точку
входа через `EngineApp::SetProjectEntry`: сначала файл, потом открытый проект. Вкладка без своих правок
сразу показывает точку входа, изменённую в Assets.

## Project Hub

`editor::ProjectHubWindow` — окно редактора, а не проекта: оно живёт при смене проектов. Его видно,
пока проект не открыт, и из меню Project → Project Hub.
- Recent — недавние проекты (настройка `Core/Project/Recent`, по строке на файл, последний первым,
  до 8; `Core/Project/Last` — последний).
- Open Project... — файл `.elmproject`.
- Create — имя (буквы, цифры, `_`, `-`) и папка, по умолчанию `projects/` движка.
  `resmgr::ProjectTemplate::Create` делает `<папка>/<Имя>/<Имя>.elmproject` с главным модулем `main`,
  `assets/scenes`, `assets/models`, `assets/scripts/main.lua` и настройку LuaLS (`.luarc.json`,
  `.meta/elm.lua` из `ScriptSystem::GenerateApiMeta`). Существующая папка — ошибка. Созданный проект
  сразу открывается.

Запуск: `--project` открывает проект, а если он не открывается — выход с ошибкой. Без `--project`
открывается последний проект; если его нет или он не открывается — Hub.

## Плеер

`EngineApp` — движок: окно, рендер, физика, скрипты, сцена, открытый проект и цикл кадра. Всё
редакторское собрано в `EditorLayer` (`src/EditorLayer.*`): ImGui и окна, меню Project, Project Hub,
недавние проекты, визуализаторы отладочных каналов редактора. Режим выбирается при запуске
(`AppMode`): `Editor` создаёт `EditorLayer`, `Player` — нет.

`Engine --project <папка или .elmproject> --player`:
- без ImGui и окон редактора; заголовок окна — имя проекта;
- сразу Play Project: стартовая сцена и главный модуль, как в редакторе по F5;
- сцена рисуется на всё окно: вид сцены подгоняется под framebuffer окна (`graphics::FitGameView`), а
  overlay-пас рисует его одним прямоугольником (`graphics::WriteGameOverlay`) — так же, как окно
  вьюпорта показывает его в редакторе;
- свободной камеры редактора нет, камерой управляют скрипты (`elm.camera`);
- Stop (`elm.engine.stop()`) завершает программу: режима Edit в плеере нет;
- `.settings` плеер только читает (корень движка, шейдеры) и не записывает;
- без `--project` плеер не запускается.

**Run Standalone** (меню Project, Ctrl+F5) запускает этот же исполняемый файл с
`--project <файл проекта> --player` отдельным процессом (`platform::StartProcess`,
`platform::CurrentExecutable`). Игра идёт по сохранённым файлам: несохранённая сцена в неё не попадёт.

## Сборка

`resmgr::ProjectBuilder::Build(project, BuildDesc)` собирает игру в `<проект>/Build/<Имя>/`:
- `<Имя>.exe` — копия программы движка (`BuildDesc::executable`, запущенный `Engine.exe`) и библиотеки
  `.dll` рядом с ней;
- `shaders/` — шейдеры движка;
- `<Имя>.elmproject` и `assets/` без `source/` и скрытых файлов (`.meta`, `.luarc.json`);
- `.settings` с `Core/FileSystem/RootPath = "."`: корень движка — папка игры;
- `.elmbuild` — метка сборки. Следующая сборка удаляет только папку с такой меткой; папку без неё не
  трогает и сообщает об ошибке.

Запуск: из редактора — Project → Build Game (путь пишется в лог), без окна — `Engine --build <папка или
.elmproject>` (выход с кодом 0 и путь сборки или 1 и ошибка). Папка `projects/*/Build/` в `.gitignore`.

Собранная игра: программа, рядом с которой лежит `<её имя>.elmproject`, — это собранная игра. Она
переходит в свою папку (там её `.settings` и шейдеры) и работает [[#Плеер|плеером]] своего проекта,
откуда бы её ни запустили. Отдельной цели сборки для плеера нет: в игру копируется тот же `Engine.exe`,
редактор в нём просто не создаётся.

## Точка входа и запуск

Старт игры всегда в одном порядке: стартовая сцена → `main.on_start` → скрипты сущностей и физика.
Подходят все три вида игр: сцена из редактора, сцена из кода, сцена плюс главный модуль-менеджер.
`Script/MainModule` переезжает из `.settings` в `entry.mainModule`. `PlayOnStart` остаётся настройкой
редактора и значит «Play Project при открытии».

`PlayMode::Play(const PlayStart&)`: снимок сцены редактора → если задана сцена, очистить и `Append` →
свежая Lua и `main.on_start` → Play. Сцену с диска заранее читает `EngineApp` через `resmgr`, `PlayMode`
файлов не касается. Плеер вызывает тот же `Play(PlayStart)`, только без Stop.

| Действие | Клавиша | Что запускается |
|---|---|---|
| Play Project | F5 | стартовая сцена и главный модуль; если стартовая сцена открыта — её версия из памяти |
| Play Scene | Shift+F5 | текущая сцена из памяти и главный модуль |
| Run Standalone | Ctrl+F5 | отдельный процесс `Engine --project <dir> --player` по файлам на диске |

Stop в обоих Play возвращает редактор в состояние до Play. `elm.engine.play()` остаётся Play Scene.
Стартовая сцена выбирается на вкладке Settings окна Project и командой «Set as Startup Scene» на его вкладке Assets.

## Этапы

1. ✅ **Проект как корень данных** ([[#Что уже есть]]).
2. ✅ **Ссылки на ассеты** ([[#Что уже есть]]). Путь ассета считается от папки `assets`, а не от корня
   проекта. Файл модели (обычный `Path`) хранит `ModelManager` рядом с моделью: `Model` — только данные,
   graphics не зависит от project. Путь ассета из него делают `Serializer` и Lua по папке `assets`.
3. ✅ **Точка входа и запуск** ([[#Что уже есть]]). Не сделано из плана: если стартовая сцена открыта в
   редакторе, Play Project всё равно читает её с диска (редактор пока не знает, какая сцена открыта, —
   этап 5). Точку входа задаёт вкладка Settings окна Project (этап 5).
4. ✅ **Ресурсы создаются в проекте** ([[#Импорт]]). Создание папок перенесено в окно Project (этап 5).
5. ✅ **Навигация** ([[#Окно Project]], [[#Project Hub]]). Не сделано из плана, на потом:
   переименование и удаление с правкой ссылок в сценах, признак изменения сцены и Save / Discard /
   Cancel, Play Project из памяти для открытой стартовой сцены (поле Scene File уже показывает
   открытую стартовую сцену), состояние редактора по
   проекту (`.elm/editor.settings`), «Show in Explorer», пункт Build.
6. ✅ **Плеер без редактора** ([[#Плеер]]). Отдельного исполняемого файла `Player` пока нет: плеер —
   это `Engine --player`; отдельная цель сборки понадобится вместе с этапом 7.
7. ✅ **Сборка** ([[#Сборка]]). Не сделано: отдельный исполняемый файл плеера без кода редактора,
   упаковка ассетов в архив, предкомпиляция Lua, выбор папки сборки.

## Проверки

Self-test:
- `ScriptSystem` Shutdown → Init с другим корнем: модули нового проекта видны, старые нет.
- `PlayStart` со сценой загружает её, Stop возвращает сцену редактора с её id.
- После Stop переменные модулей сброшены.
- В Edit `main.on_start` не вызывается.
- Нет стартовой сцены: Play не начинается, ошибка в логе.
- `AssetPath` не принимает `..` и абсолютные пути.

Вручную: смена проекта с открытыми окнами, Play/Stop в обоих режимах, импорт, окно Project.
