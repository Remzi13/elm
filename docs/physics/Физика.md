# Физика

Файлы: `physics/PhysicsSystem.*`, `Scene/PhysicsComponents.hpp`, биндинги в
`script/bindings/PhysicsBindings.cpp`. Движок физики — Jolt Physics 5.2 (`third_party/CMakeLists.txt`).

## Компоненты

Физика объекта задаётся компонентами его узла сцены (`Scene::Components<T>()`, см. [[Сцена#Компоненты]]).

| Компонент | Что задаёт |
|---|---|
| `Collider` | форма: `Box` (`halfExtents`), `Sphere` (`radius`), `Capsule` (`radius`, `halfHeight` вдоль Y); `offset` центра; `trigger` |
| `RigidBody` | `type` (`Static`, `Kinematic`, `Dynamic`), `mass`, `friction`, `restitution`, `linearDamping`, `angularDamping`, `gravityScale` |

- Тело есть только у узла с `Collider`. `Collider` без `RigidBody` — статическое тело (пол, стены).
  `RigidBody` без `Collider` ничего не делает.
- Форма задаётся в локальном пространстве узла. Мировой масштаб узла запекается в размеры формы:
  у тел Jolt нет масштаба. Сфера берёт наибольшую ось масштаба, радиус капсулы — наибольшую из X и Z.
- `Static` сам не двигается. Если узел передвинули (скрипт, редактор), тело переставляется туда же.
- `Kinematic` следует за узлом. На шаге физики тело доезжает до позы узла с нужной скоростью
  (`MoveKinematic`) и толкает динамические тела. Его самого ничто не толкает.
- `Dynamic` симулируется: после шага его поза записывается в узел. Передвинутый узел телепортирует
  тело. Динамические тела лучше держать в корне иерархии: поза пишется относительно родителя,
  каким он был до шага.

## Как тела следуют за сценой

`PhysicsSystem::Step(scene, dt)` вызывается на каждом фиксированном шаге (`EngineApp::FixedUpdate`, 60 Гц),
только в режиме Play ([[Редактор]]). Stop удаляет все тела, следующий Play строит их заново.
1. `UpdateWorldTransforms`, затем тела сверяются с компонентами. Тела удалённых узлов и узлов без
   `Collider` уничтожаются. Новый компонент получает тело. Если поменялся компонент или масштаб узла,
   тело строится заново, скорость сохраняется.
2. Поза узла сравнивается с позой тела после прошлого шага: так видно, что узел передвинули.
3. `JPH::PhysicsSystem::Update`.
4. Активные динамические тела записываются в локальные трансформы своих узлов.
5. Контакты, которые собрал `ContactListener`, становятся `CollisionEvent`: `Enter`/`Exit`, флаг
   `trigger`, для `Enter` точка и нормаль от `first` к `second`. Колбэки `ContactListener` приходят
   из рабочих потоков Jolt, поэтому очередь под мьютексом.

Затем `ScriptSystem::FixedUpdate(dt, events)` раздаёт события скриптам сущностей (`EntityScripts::DispatchCollisions`), и вызывается
`on_fixed_update`.

Тела привязаны к `NodeId`: user data тела Jolt — это `NodeId::Raw()`. `SyncNode(scene, node)` строит
тело одного узла сразу. Им пользуются биндинги, чтобы скорость можно было задать сразу после `add`.

## Триггеры

- `trigger = true` — сенсор Jolt: сообщает о входе и выходе тел и не толкает их.
- Статический триггер видит только **активные** динамические и кинематические тела. Тело, уснувшее
  внутри, «выходит» из триггера.
- Триггер не видит статические тела: оба на слое `NON_MOVING`.

Коллайдеры и триггеры видны во вьюпорте как каркасы (`ColliderVisualizer`, каналы
`Physics/Colliders` и `Physics/Triggers`, меню Debug), в Edit тоже: см. [[Отладочная отрисовка]].

## Лучи

`CastRay(origin, direction, maxDistance, ignore)` возвращает ближайшее твёрдое тело. Триггеры
пропускаются. `ignore` — узел, из которого луч выходит: луч, начатый внутри выпуклой формы,
попадает в неё же на расстоянии 0.

Каждый корректный вызов (ненулевое направление, `maxDistance > 0`) попадает в журнал кадра:
`RayQuery { origin, direction, maxDistance, hit }`.

## Журнал кадра

`FrameLog()` возвращает `PhysicsFrameLog`: что физика сделала с начала кадра.

- `rayQueries` — вызовы `CastRay`, не больше `MaxRayQueries` (256).
- `contacts` — начавшиеся контакты (`CollisionEvent` с `Enter`) всех шагов кадра, не больше
  `MaxContacts` (256). В отличие от `CollisionEvents()`, которые каждый шаг перезаписывает, они
  копятся до очистки.

Журнал — это данные для просмотра, а не состояние симуляции. `EngineApp` очищает его в начале
кадра (`ClearFrameLog`). `PhysicsFrameLog`, `RayHit`, `RayQuery` лежат в `Scene/PhysicsComponents.hpp`
рядом с `CollisionEvent`, чтобы их могли читать модули, не зависящие от физики. Ссылка на журнал
живёт, пока живёт система. Физика ничего не рисует: это делает `PhysicsVisualizer`
([[Отладочная отрисовка]]).

## Из Lua

```lua
local crate = elm.scene.spawn("Crate", elm.models.cube(1))
crate:add("Collider")                                     -- без размеров: по модели
local body = crate:add("RigidBody", { mass = 2, friction = 0.6 })
body.velocity = Vector3(0, 5, 0)                          -- тело есть сразу после add
body:add_impulse(Vector3(10, 0, 0))
crate.collider.trigger = true                             -- пишется в компонент, тело перестроится на следующем шаге
local entity, point, normal, distance = elm.physics.raycast(origin, direction, 50, self.entity)
```

## Ограничения

- Нет интерполяции: тела двигаются с частотой шага физики, между шагами узлы стоят.
- Компоненты сохраняются в [[Файл сцены]], скорости тел — нет.
- `on_*_exit` не приходит, если другое тело удалили.
- Коллизия дискретная: тонкие стены и очень быстрые тела могут проходить насквозь. Коллайдер плоской
  модели (плоскости) — коробка толщиной 0.5 под ней.
- Формы — только box, sphere, capsule. Меша и выпуклой оболочки нет.
- Не больше 8192 тел. При превышении в лог пишется одна ошибка, новые коллайдеры остаются без тела.

## Сборка

Jolt подключён к `physics` как PRIVATE. Его публичные определения (`_HAS_EXCEPTIONS=0` и другие)
не должны попадать в остальной движок: ошибки Lua летят в нём как C++-исключения. Заголовки Jolt
видит только `PhysicsSystem.cpp`, в `PhysicsSystem.hpp` только предварительные объявления.
