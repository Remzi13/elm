# Ограничения рендера

Текущие ограничения. Это кандидаты на доработку.

- **Топология и индексы.** Топология примитивов только `TriangleList`, индексы только
  32-битные ([[CommandList]]).
- **Одна текстура на пайплайн.** В пайплайне не больше одного binding'а типа `Texture`.
  DX12-бэкенд копирует её SRV в shader-visible heap на draw. Constants-буферов может быть
  несколько ([[Шейдеры и пайплайны]]).
- **Шейдеры и пайплайны только на render-потоке** (`IRenderFeature::Init`). Через
  [[RenderResources]] их не создать.
- **Фиксированные форматы 3D-вида.** Цвет всегда `RGBA8_UNORM_SRGB`, глубина `D32_FLOAT`.
  Форматы заданы в `SceneViewTargets::ColorFormat`/`DepthFormat` ([[ViewPort]], [[Ресурсы графа#Blackboard]]).
- **Линии в 1 пиксель.** `PrimitiveTopology::LineList` не умеет толщину: D3D12 и Vulkan рисуют
  линии только в пиксель ([[Отладочная отрисовка]]).
- **Последовательная трансляция.** Command list'ы транслируются в API последовательно, в один
  командный буфер (DX12 — в один native command list). Параллельно идёт только запись
  ([[Параллельная запись]]). Параллельная трансляция не потребует менять API выше бэкенда ([[Бэкенды]]).
- **Vulkan: память без суб-аллокатора.** Каждый буфер и каждое изображение получают своё
  `vkAllocateMemory`. Драйверы ограничивают число выделений (часто 4096) ([[Бэкенды#Vulkan (Linux)]]).
- **Vulkan: шейдеры собираются заранее.** Новый HLSL-файл или вариант макросов появляется только
  после сборки ([[Шейдеры и пайплайны#SPIR-V]]).
- **DX12: шейдеры собираются заранее.** Новый HLSL-файл или вариант макросов появляется только
  после сборки ([[Шейдеры и пайплайны#DXIL]]).
- **Фиксированный объём upload-памяти.** Одна арена на кадр фиксированного размера. При
  переполнении draw'ы пропускаются с ошибкой в логе ([[UploadAllocator]]).
- **Фичи регистрируются в коде.** Порядок задаётся вручную в `RenderPipeline::Init`
  ([[Фичи]]).
