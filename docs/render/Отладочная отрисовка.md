# Отладочная отрисовка

Линии и треугольники в мировых координатах поверх 3D-вида: коллайдеры, лучи, оси, границы.
Рендер ничего не знает о том, что рисуется. Он получает готовые вершины, разложенные по стилям.

```
визуализаторы (update) → DebugDraw → FrameWriter::AddDebugVertices → FrameSnapshot::debug → DebugDrawPass
```

**Слои.** В `render` только данные кадра (`DebugGeometry`) и пас. Всё, что решает, *что* рисовать
(`DebugDraw`, каналы, формы, визуализаторы), лежит в `graphics/debug` (`elm::graphics`), на стороне
редактора. Системы симуляции (`physics`, `Scene`) о отладочной отрисовке не знают: они отдают
обычные данные, а визуализатор в `graphics` превращает их в примитивы. Это касается и событий
(лучи, контакты), не только состояния.

## Система: `DebugDrawSystem`

Файл: `graphics/debug/DebugDrawSystem.*`. Вся отладочная отрисовка одного 3D-вида: накопитель
`DebugDraw` и список визуализаторов. Им владеет владелец вида: для вьюпорта движка это `EngineApp`,
у которого это единственное поле отладочной отрисовки. Синглтона нет, у превью Model Editor может
быть своя.

```cpp
// EngineApp::Init: визуализаторы, по строке на каждый
graphics::DebugDraw& debugDraw = m_debugDraw.GetDebugDraw();
m_debugDraw.AddVisualizer(MakeUnique<graphics::ColliderVisualizer>(m_scene, debugDraw));

// кадр
m_debugDraw.BeginFrame(deltaTime);  // начало кадра, до физики: состояния каналов, старение
// ... системы, скрипты и окна рисуют в m_debugDraw.GetDebugDraw()
m_debugDraw.EndFrame(frame);        // визуализаторы, запись в снимок кадра, подписи для UI
```

Это не фасад над `DebugDraw`: источники кадра (скрипты через `EngineContext::debugDraw`, окна через
`ImGuiWindowContext::debugDraw`, гизмо) получают сам `DebugDraw&` и рисуют в него напрямую.

## Накопитель: `DebugDraw`

Файл: `graphics/debug/DebugDraw.*`. Собирает примитивы одного 3D-вида на update-потоке. Им владеет
`DebugDrawSystem`.

**Каналы.** Каждый примитив рисуется в канал (`DebugChannel`, хэндл). Канал регистрируют один раз:

```cpp
m_colliders = debugDraw.RegisterChannel("Physics/Colliders", "Colliders", true);
```

- Повторная регистрация того же имени возвращает тот же канал.
- Канал включается настройкой `Render/Debug/Draw/<имя>`: состояние сохраняется в `.settings` и
  видно в окне Settings. Новый канал появляется там сам, править UI не нужно.
- Состояние читается из настроек в `BeginFrame`. Примитив выключенного или невалидного канала
  отбрасывается сразу при вызове, поэтому дорогие источники сначала спрашивают `IsEnabled`.

**Кисть.** `DebugPen { color, depth, duration }`: цвет, `DebugDepth` и время жизни в секундах.
`duration = 0` — только этот кадр. Примитив со временем живёт, пока оно не выйдет, даже если его
канал выключили (тогда он просто не рисуется).

**Формы.** `Line`, `Triangle` (заливка), `Point` (крестик), `Arrow`, `Circle`, `Axes` (X красная, Y зелёная, Z синяя),
каркасные `Box`, `Sphere`, `Capsule` (вдоль локальной Y). Формы с `transform` строятся в его
пространстве, поэтому поворот и масштаб узла применяются сами. Новая форма — это новая функция
`DebugDraw`, которая раскладывает её в отрезки: пас о формах не знает.

**Текст.** `Text(channel, position, text, pen)` — подпись в точке мира: цвет и время жизни из
кисти, каналы как у остальных примитивов. Текст не проходит через рендер: шрифтов в 3D-пасе нет.
`DebugDraw` копит подписи (`DebugLabel`), а `EngineViewportWindow` рисует их через ImGui поверх
картинки вьюпорта, проецируя точку камерой, с тенью для читаемости.

- Окна строятся раньше, чем визуализаторы дорисовывают кадр (`EndFrame`). Поэтому `EndFrame`
  после `WriteTo` вызывает `PublishLabels()`, а окно рисует `GetPublishedLabels()` — подписи
  законченного кадра. Задержка в один кадр одинакова для всех источников.
- Текст всегда поверх сцены (`pen.depth` не учитывается): буфер глубины на стороне UI не виден.
  Подпись за камерой не рисуется.

**Кадр.** `BeginFrame(dt)` читает состояния каналов и старит примитивы. `WriteTo(frame)` пишет
примитивы прямо в снимок кадра, по набору на стиль. `PublishLabels()` отдаёт подписи окну
вьюпорта на следующий кадр. Всё это вызывает `DebugDrawSystem`.

Каналы движка:

| Канал | Что | По умолчанию |
|---|---|---|
| `Editor/WorldAxes` | оси мира в начале координат, длина 2 (`WorldAxesVisualizer`) | вкл |
| `Physics/Colliders` | каркасы коллайдеров (`ColliderVisualizer`), зелёные | вкл |
| `Physics/Triggers` | каркасы триггеров, оранжевые | вкл |
| `Physics/Raycasts` | лучи `CastRay` за кадр: до попадания зелёный с крестиком и нормалью, промах красный (`PhysicsVisualizer`) | вкл |
| `Physics/Contacts` | начавшиеся контакты: крестик и нормаль, у триггеров голубой крестик; поверх сцены, живут 0,5 с | вкл |
| `Script/Default`, `Script/<имя>` | примитивы `elm.debug` из скриптов (см. ниже) | вкл, у своих каналов — как задано |
| `Editor/Gizmo` | гизмо выбранного узла (`TransformGizmo`, [[Редактор#Гизмо]]); выключенный не хватается | вкл |

Включать и выключать каналы удобно из меню **Debug** над вьюпортом движка: галка на канал,
группы по части имени до первого `/`. Галка пишет ту же настройку, что и окно Settings.

## Визуализаторы: `IDebugVisualizer`

Файл: `graphics/debug/IDebugVisualizer.hpp`. Показывает какое-то состояние движка каждый кадр:
`Draw(DebugDraw&)`. То, что он показывает, визуализатор получает в конструкторе (только для
чтения) и там же регистрирует свои каналы. `DebugDrawSystem` хранит визуализаторы и вызывает
их в `EndFrame`, когда мировые трансформы уже посчитаны.

Новая визуализация — это класс в `graphics/debug` и одна строка `AddVisualizer` в `EngineApp::Init`.

Если нужных данных нет, их отдаёт система как обычные данные (как `PhysicsSystem::FrameLog()`),
а не рисует сама. Данные, которые появляются по ходу кадра (шаги физики), система копит за кадр:
визуализатор читает их один раз, в `EndFrame`.

**`WorldAxesVisualizer`** (`graphics/debug/WorldAxesVisualizer.*`) рисует оси мира в начале координат.

**`ColliderVisualizer`** (`graphics/debug/ColliderVisualizer.*`) рисует `Collider` каждого узла:
`Box`, `Sphere` или `Capsule` в мировом трансформе узла со смещением `offset`. Формы берутся из
компонентов, а не из тел Jolt, поэтому видны и в Edit, где тел нет ([[Физика]]).

**`PhysicsVisualizer`** (`graphics/debug/PhysicsVisualizer.*`) рисует то, что физика сделала за
кадр, по журналу `PhysicsFrameLog` ([[Физика#Журнал кадра]]), который получает в конструкторе.
`EngineApp` очищает журнал в начале кадра (`ClearFrameLog`), поэтому визуализатор видит каждый луч
и каждый контакт ровно один раз.

- Лучи кадра — примитивы одного кадра. Видны лучи и из `on_update`, и из `on_fixed_update`.
- Начавшиеся контакты всех шагов кадра (шагов бывает несколько или ни одного). Метки — примитивы
  со временем `ContactLifetime`, поэтому контакт одного шага успевают заметить.

Визуализатор не знает о `PhysicsSystem`: `PhysicsFrameLog`, `RayQuery` и `CollisionEvent` лежат в
`Scene/PhysicsComponents.hpp`, так что `graphics` не зависит от `physics`.

## Из Lua: `elm.debug`

Биндинги в `script/bindings/DebugBindings.cpp`, `DebugDraw` приходит в `EngineContext::debugDraw`.
Рабочий пример — `assets/scripts/demo/debug.lua` проекта Sandbox (`entry.mainModule = demo.debug`, затем Play):
сканер со веером лучей и метками попаданий (канал `Script/sensor`), следы падающих шаров со
временем жизни (`Script/trail`), все формы `elm.debug` (`Script/shapes`); физика сама рисует
коллайдеры, триггер, лучи и контакты.

```lua
local Vector3, Vector4 = elm.math.Vector3, elm.math.Vector4
local ai = elm.debug.channel("ai")                -- канал Script/ai, появится в меню Debug

function main.on_update(dt)
    elm.debug.line(a, b)                          -- канал Script/Default, белый, один кадр
    elm.debug.sphere(target, 0.5, { color = Vector4(1, 0.5, 0, 1), channel = ai })
    elm.debug.ray(eye, forward, 10, { on_top = true })
    elm.debug.point(hit, 0.2, { duration = 2 })   -- висит 2 секунды, вызывать каждый кадр не нужно
    elm.debug.text(target, "hp " .. hp, { color = Vector4(1, 0.3, 0.3, 1) })
end
```

- Текст: `text(position, text, style?)` — подпись по центру точки, всегда поверх сцены.
- Формы: `line`, `arrow`, `ray(origin, direction, length)`, `point(position, size?)`,
  `box(center, half_extents)`, `sphere(center, radius)`, `capsule(center, radius, half_height)` —
  в мировых осях, капсула вдоль Y.
- Последний аргумент — `style`: `{ color = Vector4, duration = секунды, on_top = boolean, channel = DebugChannel }`.
  Неизвестное поле или неверный тип — ошибка Lua: опечатка не проглатывается.
- `elm.debug.channel(name, enabled_by_default?)` регистрирует `Script/<name>` (имя без `/`) и
  возвращает `DebugChannel` с полями `name` и `enabled` (чтение и запись, это та же настройка, что в
  меню Debug). Повторный вызов с тем же именем даёт тот же канал.
- **Stop** удаляет примитивы со временем из всех каналов скриптов (`ClearScriptDebugDraw`), чтобы
  после Play не оставались метки.

## Данные: `DebugGeometry`

Файл: `render/frame/DebugGeometry.hpp`.

| Тип | Что |
|---|---|
| `DebugVertex` | позиция в мире + цвет RGBA8 (`PackDebugColor`), 16 байт |
| `DebugStyle` | `DebugTopology` (`Lines`, `Triangles`) × `DebugDepth` (`Tested`, `OnTop`) |
| `DebugBatch` | диапазон вершин, нарисованный одним стилем |
| `DebugGeometry` | `vertices` + `batches`; `Clear()` сохраняет память |

- `Tested` — примитив прячется за геометрией сцены. `OnTop` — рисуется поверх всего.
- `Lines`: каждые две вершины — отрезок. `Triangles`: каждые три — треугольник.
- Цвет смешивается по альфе, глубина не пишется.

`DebugDraw::WriteTo(FrameWriter&)` пишет вершины прямо в снимок кадра через
`FrameWriter::AddDebugVertices(style, vertices)`, без промежуточной копии. Вершины того же стиля, что
и последний набор текущего вида, продлевают этот набор, поэтому у вида по набору на стиль. В снапшоте геометрия всех видов лежит в одном `FrameSnapshot::debug`, у вида — диапазон
своих наборов (`firstDebugBatch`, `debugBatchCount`), как с `drawItems`. Вид без геометрии
(превью в Model Editor) пас пропускает.

## Пас: `DebugDrawPass`

Файл: `render/passes/DebugDrawPass.*`. Стоит в [[Фичи|RenderPipeline]] между `ScenePass` и
`OverlayPass`. Для каждого вида с геометрией добавляет пас, который пишет в цвет и глубину
этого вида из `FrameBlackboard::sceneViews` ([[Ресурсы графа#Blackboard]]) без очистки.

- По пайплайну на стиль: `LineList`/`TriangleList` × тест глубины вкл/выкл. Шейдеры
  `shaders/debug.vert.hlsl`, `shaders/debug.frag.hlsl`.
- Сначала рисуются наборы `Tested`, потом `OnTop`.
- Вершины вида загружаются одним куском в [[UploadAllocator]] и рисуются `CommandList::Draw`.
  Если арена переполнена, геометрия вида пропускается с ошибкой в логе.
- **Сдвиг глубины.** Вершинный шейдер чуть приближает примитив к камере (`DepthBias`), иначе
  ребро коллайдера, совпадающее с гранью модели, мерцает. Цена — вдали линия может проступить
  сквозь очень тонкую стенку.

## Ограничения

- Линии всегда в 1 пиксель ([[Ограничения рендера]]). Толстые линии — это новый стиль: вершинный
  шейдер раздувает отрезок в квад.
- Текст рисует UI: он всегда поверх сцены, размер шрифта один, на один кадр позже линий.
- Только update-поток (`ELM_ASSERT_THREAD(Update)`): из задач `parallelFor` рисовать нельзя.
