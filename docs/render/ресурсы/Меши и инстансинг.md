# Меши и инстансинг

Геометрия (`MeshData` из `math/Primitivs.hpp`) передаётся как `render::MeshDataPtr` — это
`SharedPtr<const MeshData>`. После создания меша **её нельзя менять**: render-поток читает
те же данные.

```cpp
auto cube = MakeShared<const MeshData>(GeometryPrimitives::CreateCube(1.0f));
render::Mesh cubeMesh(resources, cube);          // RAII, один GPU-меш

// Тысяча объектов на одном меше рисуется одним instanced draw call'ом
for (int i = 0; i < 1000; ++i)
    frame.Draw(cubeMesh.GetHandle(), transforms[i], colors[i]);
```

Как отправлять объекты в кадр, описано в [[FrameWriter]].

## Правило инстансинга

Объекты с общей геометрией должны ссылаться на **один** `MeshHandle`. Render-поток сортирует
draw'ы по мешу ([[Кадр на render-потоке]]). `ScenePass` рисует каждую группу одним вызовом,
до 1024 инстансов на вызов.

> [!warning] Не создавайте меш на каждый объект
> Инстансинг перестанет работать, и вместо пары draw call'ов будет по одному на объект.

## Как это сделано в Scene

`Scene` (`Scene/TestScenes.hpp`) владеет `Vector<render::Mesh> meshes`. Инстансы хранят
только хэндл и указатель на данные, которые нужны программному culling'у.

```cpp
Scene::Instance a = scene.MakeInstance(resources, GeometryPrimitives::CreateCube(1.0f)); // новый меш
Scene::Instance b = scene.MakeInstance(scene.meshes.back());                            // тот же меш
```

## Формат данных инстанса

`render::InstanceData { Matrix4x4 transform; Vector4 color; }` — 80 байт, кладётся во второй
вершинный поток как есть. Как этот поток привязывается, показано в [[CommandList]].
