# Бэкенды

Всё, что выше `rhi::IRenderBackend` (`render/rhi/IRenderBackend.hpp`), не зависит от
графического API:
- [[RenderGraph]];
- [[Фичи]];
- `RenderSystem`.

Бэкенд выбирается по платформе в `src/render/CMakeLists.txt`: собирается только он, а его
графический API подключён к `render` как **PRIVATE**-зависимость.

| Платформа | Бэкенд | Каталог |
|---|---|---|
| Linux | `VulkanBackend` (свой, Vulkan 1.3) | `render/backend/vulkan/` |
| Windows | `DiligentBackend` (D3D12) | `render/backend/diligent/` |

Свой D3D12-бэкенд для Windows — следующий шаг, после него Diligent уйдёт из проекта.

## Vulkan (Linux)

`render/backend/vulkan/`, пространство имён `elm::render::vulkan`. Заголовки Vulkan видны только
здесь, Xlib и Wayland — только в `VulkanSurface.cpp`.

Требования к GPU: Vulkan 1.3 (`dynamicRendering`, `synchronization2`) и `VK_KHR_push_descriptor`.
Для сборки нужны заголовки и загрузчик Vulkan (`libvulkan-dev`). Компилятор шейдеров DXC проект скачивает сам ([[Шейдеры и пайплайны#SPIR-V]]).

| Класс | За что отвечает |
|---|---|
| `VulkanBackend` | фасад `IRenderBackend`: реестры ресурсов по [[Хэндлы\|хэндлам]], кадр, сабмит, present |
| `VulkanDevice` | instance, выбор GPU (дискретная первой), device, очередь графики и present, учёт памяти |
| `VulkanSwapChain` | поверхность окна, swapchain, семафоры acquire/present, пересоздание при ресайзе |
| `VulkanFrame` | кадр в полёте: командный буфер, fence, host-visible память кадра, отложенное удаление |
| `VulkanBuffer`, `VulkanImage` | RAII-буфер и RAII-изображение (с view и текущим layout) на своей памяти |
| `VulkanPipeline` | graphics pipeline под dynamic rendering, layout на push-дескрипторах |
| `VulkanBackend::CommandTranslator` | перевод [[CommandList]] в команды Vulkan |
| `SpirvShader`, `RemapBindings` | SPIR-V с диска и перенумерация его биндингов |

Как устроен кадр:
- **Один командный буфер на кадр.** Команды ресурсов, все [[CommandList]] и переходы layout'ов
  пишутся в буфер текущего `VulkanFrame`. Первый `Present` отправляет его в очередь: ждёт
  acquire каждой поверхности, в которую рисовал кадр, и сигналит её present-семафор.
- **Два кадра в полёте** (`FramesInFlight`). Перед записью кадр ждёт свой fence.
- **Upload-память.** `Submit` копирует использованную часть арен вершин и индексов
  [[UploadAllocator]] в host-visible буферы кадра. Константы копируются поблочно
  (`WriteConstants`) с выравниванием uniform-буферов.
- **Загрузка ресурсов.** Меши, буферы и текстуры живут в device-local памяти и заполняются
  через staging-буфер кадра. Барьеры ставятся до и после копии.
- **Ресурсы на draw.** Push-дескрипторы: binding `i` — это `PipelineDesc::bindings[i]`,
  сэмплеры идут следом. Сэмплер linear clamp неизменяемый, он вшит в layout.
- **Layout'ы.** Каждое `VulkanImage` помнит свой layout. Барьеры графа, render pass'ы и draw'ы
  переводят его куда нужно. Если текстуре нужен другой layout посреди pass'а, pass
  приостанавливается и продолжается с загрузкой содержимого.
- **Удаление.** Удалённые ресурсы и пайплайны уходят в `VulkanFrame::Retire` и
  освобождаются, когда GPU закончил этот кадр ([[Время жизни ресурсов]]).
- **Поверхности.** Формат выбирается по главному окну: сначала sRGB (`B8G8R8A8_SRGB`), как было в
  Diligent. Окна ImGui используют тот же формат. Depth-буфера у поверхностей нет
  (`GetSurfaceDepthFormat` → `Unknown`). Present идёт в режиме FIFO (vsync).
- **Ось Y.** Viewport с отрицательной высотой: clip space такой же, как в D3D, шейдеры и
  матрицы общие с Diligent.
- **Валидация.** В Debug включается `VK_LAYER_KHRONOS_validation`, если слой установлен.
  Сообщения слоя идут в лог (`Render`, источник `Vulkan`).

Ограничения: у каждого буфера и изображения своё выделение `vkAllocateMemory`, без
суб-аллокатора. Для тысяч ресурсов этого не хватит ([[Ограничения рендера]]).

## Diligent (Windows)

`render/backend/diligent/`: D3D12. Diligent скачивается только на Windows.

Что делает бэкенд:
- **Ресурсы.** Владеет устройством, swap chain'ами и всеми ресурсами по [[Хэндлы|хэндлам]].
- **Upload-память.** В `Submit` копирует использованную часть [[UploadAllocator]] на GPU.
- **Трансляция.** Переводит [[CommandList]] в вызовы Diligent и кэширует один SRB на каждую
  подключённую текстуру.

## Null

`render/backend/null/`. Ничего не рисует: ведёт учёт ресурсов и считает команды и draw call'ы.

Полезен в трёх случаях:
- headless-прогоны;
- тесты логики кадра;
- проверка, что код выше бэкенда не зависит от графического API.

Сейчас его ветки в CMake нет: чтобы собрать с ним, подключи `backend/null/` вместо бэкенда платформы.

Окно при этом создаётся, но остаётся пустым.

## Окно

Окно создаёт `platform::Window` (GLFW), а не рендер. `RenderSystem::Init` получает только
`render::NativeWindow { handle, display, system }` и размер, где `WindowSystem` — Win32, X11 или Wayland ([[Главный цикл]]).
