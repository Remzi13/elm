# Новый бэкенд

## 1. Реализовать `rhi::IRenderBackend`

| Группа | Методы | Заметки |
|---|---|---|
| Жизненный цикл | `GetName`, `Init(NativeWindow, Size)`, `Shutdown` | |
| Ресурсы update-стороны | `ExecuteResourceCommands`, `GetTextureDesc` | команды из `render/api/ResourceCommands.hpp` ([[RenderResources]]) |
| Render-side объекты | `CreateTransientTexture` / `DestroyTransientTexture`, `CreateShader`, `CreatePipeline` / `DestroyPipeline` | хэндлы transient-текстур не должны пересекаться с хэндлами update-стороны ([[Хэндлы]]) |
| Окна | `CreateSurface`, `DestroySurface`, `ResizeSurface`, `HasSurface`, `Present`, `GetSurfaceColorFormat` / `GetSurfaceDepthFormat` | `MainSurface = 0` |
| Кадр | `Submit(lists, uploads)` → `SubmitStats` | сначала загрузить арены ([[UploadAllocator]]: `GetData` / `GetUsedSize`), затем транслировать [[CommandList]] по порядку, каждый с чистого состояния |
| Статистика | `GetAllocatedMemory` | |

## 2. Определить фабрику

```cpp
namespace elm::render::rhi {
    UniquePtr<IRenderBackend> createRenderBackend() { return MakeUnique<my::MyBackend>(); }
}
```

## 3. Подключить в CMake

Добавить ветку в `src/render/CMakeLists.txt` по образцу `Diligent`/`Null`. Зависимость от
графического API подключается как `PRIVATE`.

## С чего начать

Минимальная корректная реализация — `render/backend/null/NullBackend.cpp`. С неё удобно
начать, потом наполнить реальными вызовами по образцу `DiligentBackend.cpp`.
