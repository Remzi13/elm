# Шейдеры и пайплайны

Описания: `render/api/PipelineDesc.hpp`. Шейдеры и пайплайны создаются в `Init`
[[Фичи|фичи]] на render-потоке через `rhi::IRenderBackend`. Шейдер — это HLSL из каталога
`shaders/`, точка входа `main`.

```cpp
const auto vs = backend.CreateShader({ "Mesh VS", ShaderStage::Vertex, "mesh.vert.hlsl", {} });

ShaderDesc psDesc { "Tint PS", ShaderStage::Pixel, "tint.frag.hlsl", {} };
psDesc.macros.push_back({ "USE_TINT", "1" });
const auto ps = backend.CreateShader(psDesc);

PipelineDesc desc;
desc.name         = "Tint";
desc.vertexShader = vs;
desc.pixelShader  = ps;
desc.vertexLayout = {                       // { location, bufferSlot, format, perInstance }
    { 0, 0, VertexFormat::Float3, false },
    { 1, 0, VertexFormat::Float3, false },
    { 2, 0, VertexFormat::Float2, false },
};
desc.colorFormat = TextureFormat::RGBA8_UNORM_SRGB;  // должен совпадать с форматом таргета
desc.depthFormat = TextureFormat::D32_FLOAT;         // Unknown — без depth
desc.topology    = PrimitiveTopology::TriangleList;  // или LineList (линии всегда в 1 пиксель)
desc.blend       = BlendMode::AlphaBlend;            // Opaque / PremultipliedAlpha / AlphaBlend
desc.depthTest   = true;
desc.bindings = {
    { "Constants", ShaderStage::Vertex, BindingType::Constants, sizeof(Constants) }, // slot 0
    { "g_Texture", ShaderStage::Pixel,  BindingType::Texture,   0 },                 // slot 1
};
desc.samplers = { { "g_Texture", ShaderStage::Pixel } };  // linear clamp -> "g_Texture_sampler"

m_pipeline = backend.CreatePipeline(desc);   // невалидный хэндл = ошибка, текст уже в логе
```

Форматы атрибутов: `Float2`, `Float3`, `Float4` и `UNorm8x4` — четыре байта, которые в
шейдере приходят как `float4` в [0, 1] (упакованный RGBA-цвет, 4 байта вместо 16).

## Слоты

Индекс в `bindings` — это слот для `SetConstants`/`BindTexture` в [[CommandList]]. Имя
binding'а должно совпадать с именем ресурса в HLSL (`cbuffer Constants`, `Texture2D g_Texture`).

## SPIR-V

Vulkan-бэкенд ([[Бэкенды]]) не компилирует HLSL при запуске. Шейдеры собирает CMake
(`cmake/Shaders.cmake`): DXC переводит каждый `shaders/*.vert.hlsl` и
`shaders/*.frag.hlsl` в `shaders/spirv/<имя>.spv`. Папка `spirv/` лежит рядом с исходниками,
потому что шейдеры ищутся от корня движка, и в git не попадает. Сборка игры копирует её
вместе с `shaders/`.

Макросы `ShaderDesc::macros` дают отдельный файл: `overlay.frag.hlsl` с `OVERLAY_MANUAL_SRGB=1`
превращается в `spirv/overlay.frag.OVERLAY_MANUAL_SRGB_1.spv`. Такой вариант нужно объявить в
`VARIANTS` у `elm_add_spirv_shaders` в `src/render/CMakeLists.txt`, иначе `CreateShader` не
найдёт файл и запишет ошибку в лог.

## DXIL

Direct3D 12-бэкенд ([[Бэкенды]]) тоже не компилирует HLSL при запуске. DXC собирает файлы
в `shaders/dxil/<имя>.dxil`; варианты макросов объявляются в `VARIANTS` у
`elm_add_dxil_shaders` и получают суффикс `<МАКРОС>_<ЗНАЧЕНИЕ>`. Файлы генерируются рядом
с исходниками и не попадают в git.

DXC — зафиксированный релиз Microsoft (v1.8.2505), FetchContent скачивает его в `../elm_deps/dxc-src`
вместе с остальными зависимостями и сверяет SHA256. Свой компилятор задаётся явно, тогда
релиз не скачивается:

```bash
cmake -S . -B build -DELM_DXC_EXECUTABLE=/path/to/dxc
```

Правила для HLSL:
- **Входы VS объявлены по порядку `ATTRIBn`.** DXC нумерует location'ы в порядке объявления
  полей, а не по номеру семантики.
- **Выходы VS и входы PS** — одна и та же структура в одном порядке: стадии сопоставляются по
  location, а не по имени семантики.
- **Порядок ресурсов.** Root signature DX12 сопоставляет `cbuffer` в порядке `bindings`
  с `b0`, `b1` и далее отдельно для каждой стадии; текстура и сэмплер занимают `t0`/`s0`.
  Vulkan перенумеровывает ресурсы по имени через `RemapBindings`.
- **`MatrixFromRows`** задаётся макросом `ELM_DXC_COMPAT_DEFINES` в `cmake/Shaders.cmake`.
