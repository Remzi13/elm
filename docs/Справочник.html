Сцена, узлы и NodeId

Scene::Node — только ядро: id, родитель, имя, локальный трансформ. Всё остальное — компоненты в хранилищах scene.Components<T>(). Узлы лежат плоским массивом, родитель всегда раньше детей.

NodeId вместо индекса

Индекс узла сдвигается при удалении и живёт одну операцию. Дольше держат NodeId: 24 бита слота и 8 бит поколения.

Запись только методами сцены

AddNode, RemoveNode, SetParent, SetLocalTransform, SetWorldTransform, SetName. Устаревший id ничего не меняет: false, пустой id или StaleNode.

Мировые трансформы

Производный массив WorldTransforms(). Один линейный проход: world[i] = world[parent] * local[i].

Компоненты

Закрытый список ComponentType: Script, RigidBody, Collider, Model. Простые struct без логики, sparse set по NodeId.

Песочница NodeIdTable

Добавляйте и удаляйте узлы, запоминайте их id и смотрите, какие ссылки остаются рабочими. Нажмите Play, создайте узлы, затем Stop: сцена вернётся из снимка, а id, выданные во время Play, не оживут. Это модель поведения, а не сам код движка.

Файл .scene

JSON, пишется formatVersion 6, читаются версии 1–6. Модели лежат отдельными .model в assets/models. Родитель — индекс в nodes, ссылки на сущности в props — { "entity": индекс }. Меняете формат: поднимите версию и сохраните чтение старых.

Edit и Play

Движок стартует в Edit: сцена — это данные. Play (F5, кнопка над вьюпортом, elm.engine.play()) включает физику и скрипты сущностей. Переключение выполняется в начале следующего обновления, в PlayMode::ApplyRequest.

Что происходит при переходах

Play
  1. SceneSnapshot: узлы с их id, компоненты, список моделей.
  2. main.on_play(), затем на этом же кадре on_start у скриптов сущностей.
Stop
  1. on_destroy у скриптов сущностей, затем main.on_stop().
  2. Тела физики удаляются, на следующем Play строятся из компонентов.
  3. Снимок возвращается вместе с id узлов. Ссылки, взятые до Play, снова рабочие. Сущности из Play остаются недействительными.
src/script · Lua 5.4.7, своя обёртка над C API

Скрипты на Lua

ScriptSystem — только менеджер: открывает Lua-машину, собирает части и ведёт их по кадру. Работу делают части в слоях, зависимость идёт только вниз, части одного слоя друг о друге не знают. Нажмите на слой.

Lua собрана как C++: lua_error бросает исключение и разматывает C++-кадры биндингов. Подключайте только script/lua/Lua.hpp, никогда lua.hpp.

Скрипт сущности

Модуль возвращает класс: методы и props по умолчанию. Каждая сущность с компонентом Script получает свой экземпляр self, класс стоит у него в __index.

-- assets/scripts/npc/guard.lua
local Guard = { props = { speed = 2.5, view_distance = 8 } }

function Guard:on_start() self.post = self.entity.position end
function Guard:on_update(dt) --[[ ... ]] end
return Guard

-- где-то в главном модуле
local npc = elm.scene.spawn("Guard 1", cube)
local guard = npc:add("Script", { module = "npc.guard", props = { speed = 3 } })
print(guard.speed, npc.script == guard)    -- 3  true

Hot reload

Опрос 4 раза в секунду. Таблица модуля патчится на месте, экземпляры сразу выполняют новый код и сохраняют поля self. Упала компиляция — работает старая версия.

Состояние между перезагрузками

Локальные переменные модуля начинаются заново. Нужное держите в elm.script.persist(key, default) или переносите в on_reload(previous).

Ошибка в хуке

Останавливает только этот экземпляр. Одинаковые ошибки разных экземпляров пишутся в лог один раз. Успешная перезагрузка снимает остановку.

Песочница

Нет io, os, dofile, package.path. load только текстом. debug открыт в debug-сборке.

Lua API

Модули движка для скриптов и консоли окна Scripts. Аннотации для LuaLS генерирует Engine --dump-script-api. Если системы нет (инструменты, самотесты), её функции бросают ошибку «not available here».

Соглашения: векторы-столбцы, трансформ T * R * S, углы в радианах, Эйлер (pitch, yaw, roll), индексы матрицы с 1. Vector3 в Lua изменяемый: b = a — алиас, копия — a:copy().

src/physics · Jolt виден только в PhysicsSystem.cpp

Физика

Тело есть только у узла с Collider. Collider без RigidBody — статическое тело. RigidBody без Collider ничего не делает. Тела привязаны к NodeId. Выберите тип тела.

Шаг физики

1UpdateWorldTransforms, тела сверяются с компонентами: лишние удаляются, новые строятся, изменённые перестраиваются с сохранением скорости.
2Поза узла сравнивается с позой тела после прошлого шага: так видно, что узел передвинули.
3JPH::PhysicsSystem::Update.
4Активные динамические тела пишутся в локальные трансформы своих узлов.
5Контакты из ContactListener становятся CollisionEvent (Enter/Exit, trigger, точка и нормаль).
local crate = elm.scene.spawn("Crate", elm.models.cube(1))
crate:add("Collider")                                -- без размеров: по модели
local body = crate:add("RigidBody", { mass = 2, friction = 0.6 })
body.velocity = Vector3(0, 5, 0)                     -- тело есть сразу после add
local entity, point, normal, distance = elm.physics.raycast(origin, direction, 50, self.entity)

Ограничения: нет интерполяции, коллизия дискретная, формы только box, sphere, capsule, не больше 8192 тел, скорости в файл сцены не сохраняются.

src/render · rhi::IRenderBackend

Рендер

Update пишет команды ресурсов в RenderResources и данные кадра в FrameWriter. Снимок FrameSnapshot уходит render-потоку через FrameRing. Там фичи объявляют пасы в RenderGraph, граф сам упорядочивает их и ставит барьеры.

Хэндлы ресурсов

TextureHandle, MeshHandle, BufferHandle создаются из любого потока и возвращаются сразу. Удалённый ресурс не проходит проверку поколения, отрисовка с ним пропускается.

Фичи

IRenderFeature: Init создаёт шейдеры и пайплайны, Setup каждый кадр только объявляет пасы. Сейчас ScenePass и OverlayPass.

Compile()

Отсекает пасы, чей результат никто не читает, раскладывает по уровням, вставляет переходы состояний. Пасы одного уровня пишутся параллельно.

Бэкенды

DiligentBackend (D3D12 / Vulkan) или NullBackend для headless-прогонов. Выбор: -DELM_RENDER_BACKEND=Diligent|Null.

graph.AddPass<Data>("MyPass",
    [&](PassBuilder& builder, Data& data) {          // setup: сразу, объявляет ресурсы
        data.color = builder.WriteColor(target);
        data.depth = builder.WriteDepth(builder.CreateTexture("MyDepth", depthDesc));
    },
    [pipeline = m_pipeline](const Data& data, PassContext& context) {   // execute: позже, возможно на воркере
        auto& cmd = context.Commands();
    });
Execute-лямбда вызывается после выхода из setup. Локальные переменные setup не захватывайте по ссылке: берите хэндлы по значению, а данные кадра из context.Frame(). RAII-ресурсы (Texture, Mesh, ViewPort, ModelManager) уничтожаются до RenderSystem::Shutdown().
