    Первый проект: вертушка

    За десять шагов вы создадите проект, соберёте сцену из пола и куба, импортируете модель, напишете скрипт, который крутит куб, запустите игру в редакторе и отдельным окном и соберёте её в папку с .exe. Справа видно, что лежит в папке проекта после каждого шага; файлы можно открыть.

    Шаг 1

    Подготовка: собрать и запустить редактор

    Редактор и игра — одна программа, Engine.exe. Соберите её один раз; первая конфигурация долго качает зависимости в ../elm_deps.

    1. Сконфигурируйте и соберите движок из корня репозитория: 
      cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug -j
    2. Запустите редактор без аргументов: 
      build/Debug/Engine.exe

      Без --project редактор открывает проект, с которым работал в прошлый раз. Если такого нет, он покажет окно Project Hub — оно и нужно.

    Что важно знать о запуске

    Файл .settings ищется вверх от текущей папки, поэтому запускать можно из корня или из build/. В нём хранятся настройки редактора: недавние проекты, каналы отладочной отрисовки, корень движка.

    Открыть конкретный проект сразу: Engine.exe --project projects/MyGame. Проверить движок без окна: Engine.exe --script-selftest.

    Шаг 2

    Создать пустой проект

    Проект — это папка с именем игры. В ней файл MyGame.elmproject (имя и точка входа) и папка assets со всем, что игра загружает.

    1. Откройте Project Hub, если он ещё не открыт: меню Project→Project Hub...
    2. В разделе Create введите имя и оставьте папку по умолчанию: Name: MyGameLocation: …/projectsCreate Project

      Имя — буквы, цифры, _ и -: это ещё и имя папки, и имя будущего .exe.

    3. Проект откроется сам: заголовок меню Project покажет MyGame, появятся окна проекта.
    Что создаёт шаблон

    MyGame.elmproject с главным модулем main, пустые scenes/ и models/, scripts/main.lua и настройку подсказок для редактора кода: .luarc.json и .meta/elm.lua с описанием всего Lua API движка. Откройте scripts в VS Code с расширением Lua — появятся подсказки по elm.*.

    Существующую папку шаблон не перезаписывает: имя должно быть новым.

    Шаг 3

    Окна редактора

    Окна можно таскать и стыковать; скрытые включаются в меню Windows. Нажмите на окно на схеме, чтобы узнать, зачем оно.

    Выберите окно на схеме.
    Расположение окон хранится в imgui.ini и остаётся при смене проекта.
    Шаг 4

    Сцена: пол и куб

    1. Начните новую сцену и назовите её: Scene Hierarchy→New→Scene File: level.scene

      New очищает сцену и даёт ей свободное имя (new.scene), чтобы Save случайно не перезаписал другую сцену. Имя в поле — относительно assets/scenes.

    2. Добавьте пол и куб: + Add Object...→3D Primitives→Ground Plane + Add Object...→3D Primitives→Cube
    3. Выберите Cube и поднимите его над полом: в деталях узла Position = 0, 0.5, 0 (или тащите стрелку гизмо во вьюпорте).
    4. Сохраните сцену кнопкой Save.

      Вместе со сценой в assets/models/ записываются модели, у которых ещё нет файла: Cube.model и Ground Plane.model. Сама сцена ссылается на них путями.

    5. Сделайте её стартовой — с неё начнётся игра: Project→scenes/level.scene→правая кнопка→Set as Startup Scene

      Нет level.scene в дереве — нажмите Refresh. Можно и на вкладке Settings окна Project: Startup scene → Save.

    Как выглядит файл сцены

    Сцена — JSON версии 7. Модели перечислены путями от папки assets, узлы ссылаются на них индексом. Откройте level.scene справа.

    Шаг 5

    Модель из glTF

    Файлы извне попадают в проект только через импорт: оригинал копируется в assets/source/, а модели записываются в assets/models/ в формате движка .model.

    1. Импортируйте сцену glTF (подойдёт пример из Sandbox: projects/Sandbox/assets/test/village/village.gltf): Scene Hierarchy→Import glTF...→village.gltf

      Узлы glTF появятся в иерархии с моделями. В проекте: source/village/village.gltf вместе с village.bin и новые .model.

    2. Или одна модель целиком: + Add Object...→Model from Disk (.gltf, .glb, .model)...
    3. Модели проекта можно перетаскивать: возьмите .model в окне Project и бросьте в дерево Scene Hierarchy — получится новый узел.
    4. Сохраните сцену (Save).
    Правка модели

    Двойной клик по .model в окне Project открывает её в Model Editor (сабмеши, цвета, трансформ геометрии). Apply to Scene заменяет модель в сцене; с несохранёнными правками она станет новой моделью и запишется со сценой отдельным файлом — сохраните её (Save), чтобы сцена ссылалась на её файл.

    Повторный импорт того же файла не перезаписывает старый: оригинал ляжет в source/village_1/, модели — с номером в имени.
    Шаг 6

    Скрипт, который крутит куб

    Скрипт сущности — Lua-класс. Его экземпляр живёт на узле с компонентом Script; поля props видны и правятся в Scene Hierarchy.

    1. Создайте файл: Scripts→Editor→folder/name.lua: spinner→New file

      Откроется шаблон с props, on_start и on_update.

    2. Замените текст и сохраните Ctrl+S:
      assets/scripts/spinner.lua
    3. Повесьте скрипт на куб: Scene Hierarchy→Cube→+ Add Component→Script Component (Lua)→spinner

      В Scene Hierarchy, в разделе Script Component, появится prop speed со значением 1.5 из скрипта. Изменённый prop подсвечен синим и сохраняется в сцене для этого узла; Reset вернёт значение из скрипта.

    4. Сохраните сцену (Save).
    Почему куб пока не крутится

    В режиме Edit сцена — это данные: физика, скрипты сущностей и главный модуль стоят. Всё запустится по Play (шаг 8).

    Шаг 7

    Главный модуль: камера

    Точка входа проекта — стартовая сцена и главный модуль (entry в MyGame.elmproject). Главный модуль работает только в Play: с ним стартует игра. Поставим камеру так, чтобы куб было видно.

    1. Откройте main.lua: двойной клик в окне Project по scripts/main.lua.
    2. Замените текст и сохраните Ctrl+S:
      assets/scripts/main.lua
    3. Проверьте точку входа: окно Project → вкладка Settings. Startup scene — scenes/level.scene, Main module — main.
    Хуки главного модуля

    on_start — начало игры (после загрузки стартовой сцены), on_play — сразу за ним, on_update(dt) и on_fixed_update(dt) — каждый кадр и шаг физики, on_stop — при Stop, on_shutdown — когда Lua-машина игры закрывается.

    Главного модуля может и не быть, как и стартовой сцены, — но хотя бы что-то одно в entry должно быть.

    Шаг 8

    Запуск в редакторе

    1. Нажмите Play Project над вьюпортом или F5.

      Игра стартует как у игрока: свежая Lua-машина, стартовая сцена с диска, main.on_start. Куб крутится, Space меняет направление.

    2. Пока игра идёт, поменяйте speed в spinner.lua и сохраните Ctrl+S — модуль перезагрузится на ходу. Или поменяйте prop speed в Scene Hierarchy.
    3. Остановите: Stop или снова F5. Сцена вернётся к тому виду, что была до Play; правки в Play пропадут.
    Play Scene (Shift+F5) играет сцену, открытую в редакторе, из памяти — удобно проверить уровень, не начиная игру сначала. Play Project читает стартовую сцену с диска: не забудьте её сохранить.
    Что живёт между Play

    Ничего из Lua: каждый Play и Stop дают свежую Lua-машину, глобальные переменные и persist не переживают Play. Сцена после Stop восстанавливается из снимка вместе с id узлов.

    Шаг 9

    Игра отдельным окном

    1. Запустите плеер: меню Project→Run StandaloneилиCtrl+F5

      Откроется отдельное окно «MyGame» без интерфейса редактора: игра на весь экран, сразу Play Project. Она идёт по сохранённым файлам.

    2. То же из командной строки: 
      build/Debug/Engine.exe --project projects/MyGame --player
    В плеере нет режима Edit: elm.engine.stop() из скрипта завершает программу. Свободной камеры редактора тоже нет — камерой управляют скрипты.
    Шаг 10

    Сборка готовой игры

    1. Соберите игру: меню Project→Build Game

      Путь к сборке появится в окне Log. Без редактора то же самое делает команда:

      build/Debug/Engine.exe --build projects/MyGame
    2. Запустите projects/MyGame/Build/MyGame/MyGame.exe — двойным кликом, без аргументов.

      Программа находит рядом с собой MyGame.elmproject, переходит в свою папку и играет проект. Папку можно скопировать на другой компьютер целиком.

    Что попадает в сборку

    MyGame.exe (копия движка) и библиотеки рядом, shaders/, MyGame.elmproject, assets/ без source/ и скрытых файлов (.meta, .luarc.json), .settings с корнем движка в папке игры и метка .elmbuild. Следующая сборка заменяет только папку с такой меткой.

    Папки projects/*/Build/ не попадают в git.
